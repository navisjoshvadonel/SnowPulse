## 2024-10-09 - O(N^2) Correlation Matrix Bottleneck
**Learning:** Found a severe performance bottleneck where `CorrelationMatrix` was being computed using an explicit nested O(N^2) loop over DataFrame columns. Instead of generating a full 2D array and passing it to `np.corrcoef`, Polars dataframes were being incorrectly iterated and split into 1D numpy arrays, calling `np.corrcoef(arr_a, arr_b)` individually for every column pair combination. For large datasets with many numeric features, this causes a major slowdown (from sub-second to multiple seconds execution times).
**Action:** Always prefer fully vectorized operations in numpy/polars (e.g., using `np.corrcoef` on 2D arrays with `rowvar=False`) over explicit Python nested loops. Ensure to wrap `np.corrcoef` with `np.atleast_2d()` when column counts are dynamic to prevent indexing errors on single-column inputs, and use `np.errstate(invalid='ignore', divide='ignore')` to cleanly handle zero-variance columns producing NaNs.
